# v86 Integration Guide

## What is v86?

**v86** is a JavaScript-based x86 CPU emulator that runs in the browser via WebAssembly. It provides a full PC environment with various Linux distributions, enabling complete system emulation without installation.

### Key Features

- 🖥️ **Full x86 Emulation** - Complete processor and memory emulation
- 🐧 **Multiple Linux Distributions** - Ubuntu, Arch Linux, Fedora, and more
- ⚡ **WebAssembly Powered** - Fast, client-side execution
- 🔧 **System Tools** - Access to full package managers and development tools
- 💾 **Persistent Storage** - Save your work between sessions
- 🌐 **Browser Native** - No installation or downloads needed

## Quick Start with v86

### 1. Access v86
Click the **"Open v86 (Arch Linux) →"** button in the eBPF Builder Deploy modal, or visit:
```
https://copy.sh/v86/?profile=archlinux
```

### 2. Copy the Setup Command
The integration automatically copies the setup command:
```bash
git clone https://github.com/qweralfredo/ebpf-design.git && cd ebpf-design && npm install && npm run dev
```

### 3. Paste in v86 Terminal
Once v86 boots (takes ~30-60 seconds), paste the command in the terminal:
```bash
user@archlinux:~# git clone https://github.com/qweralfredo/ebpf-design.git
```

### 4. Wait for Installation
The npm install and npm run dev will start automatically. Wait for the development server to start:
```
➜  Local:   http://localhost:3007/
```

### 5. Access the Application
Open a new tab and navigate to `http://localhost:3007` to access the eBPF Builder running inside v86.

## Using v86 for eBPF Development

### Full Linux Environment

v86 provides a complete Arch Linux environment with:

- **Package Management**: `pacman`, `yay` for installing tools
- **Development Tools**: gcc, clang, llvm, make, cmake
- **Version Control**: Git, GitHub integration
- **Node.js/npm**: Already included in the image
- **eBPF Tools**: LLVM, libbpf, BCC available via pacman

### Installation of Additional Tools

Once in v86:

```bash
# Update package database
sudo pacman -Sy

# Install specific tools
sudo pacman -S llvm clang libbpf

# Install other development tools
sudo pacman -S gcc make git
```

### Testing eBPF Programs

1. **Generate Code** in eBPF Builder
2. **Download Files** or access via localhost:3007
3. **Compile** with the provided Makefile
4. **Load and Test** with full kernel access

### Saving Your Work

#### Option 1: Download Files
- Use the Download functionality to get your files locally
- Continue work on your machine

#### Option 2: GitHub Integration
- Push code to GitHub from within v86
- Clone on your next v86 session
- Persistent version control

#### Option 3: v86 Snapshots
- v86 can save VM state (if enabled)
- Resume exactly where you left off

## v86 vs WebVM.io Comparison

| Feature | v86 | WebVM |
|---------|-----|-------|
| **Environment Type** | Full x86 PC | Linux Kernel only |
| **Boot Time** | 30-60 seconds | 5-10 seconds |
| **System Tools** | Full access | Limited |
| **Package Manager** | pacman (Arch) | apt (Alpine/Ubuntu) |
| **Performance** | Slower (full emulation) | Faster (kernel only) |
| **Use Case** | Comprehensive testing | Quick development |
| **Memory Footprint** | Larger | Smaller |

## Troubleshooting

### v86 Won't Load
- **Check Your Internet**: v86 downloads are substantial (50-100MB+)
- **Wait Longer**: Initial boot can take up to 2 minutes
- **Clear Browser Cache**: Try incognito/private mode
- **Use Different Profile**: Try `?profile=ubuntu` instead of archlinux

### npm install Hangs
- **Check Disk Space**: v86 emulated drive might be full
- **Slow Network**: npm downloads can be slow over WebAssembly
- **Reboot v86**: Close and reload the page

### Cannot Access localhost:3007
- **Wait for npm run dev**: Server takes 10-20 seconds to start
- **Check Console**: Look for error messages in v86 terminal
- **Port Already Used**: Try different port or restart v86

### Copy Command Doesn't Work
- **Enable Clipboard**: Some browsers need permission
- **Manual Copy**: Copy the command from the modal text
- **Use Paste**: Different v86 instances may have isolated clipboards
